# Проверка локальных слушателей Android — 1.9.2

Область проверки: сценарии из [VLESS-SOCKS5-vulnerability](https://wiki.zapret.moe/VLESS-SOCKS5-vulnerability) и [happ-problems](https://wiki.zapret.moe/xray/happ-problems): обход выбора приложений через localhost, открытый API управления, влияние подписки на настройки и передача ссылок сервисам расшифровки. Это проверка указанных сценариев, а не заявление об отсутствии всех уязвимостей.

| Сценарий | Поведение qThrone |
| --- | --- |
| Анонимный SOCKS/HTTP/DNS в обычном VPN | Генератор не открывает эти слушатели: трафик принимает native TUN. Ручная раздача VPN — отдельная настройка с авторизацией. |
| Внутренние мосты sing-box ↔ Xray | Loopback, случайные 32-символьные реквизиты на каждую генерацию. SOCKS4 не допускается Xray при включённом пароле. |
| Xray HandlerService / gRPC API | Приложение не генерирует такой API. В 1.9.2 проверяются все Xray-документы перед запуском, включая полные конфиги и участников автовыбора/пинга. Конфиг с API отклоняется. |
| Пользовательский sing-box JSON с открытой API-службой | В 1.9.2 закрыт пробел проверки `services`: API с TCP-портом требует loopback и секрет от 32 символов. In-process статистика с портом 0 разрешена. Открытый V2Ray API отклоняется. |
| Пользовательские локальные прокси | В VPN и при пинге допускаются только поддерживаемые входы с авторизацией; слабые пароли и публичные Xray-входы отклоняются. |
| Управление защитой заголовками подписки | `socks-auth-mode` / `http-auth-mode` не применяются к локальной авторизации. Подписка не может снять защиту слушателей. Настройки HWID контролируются пользователем. |
| Расшифровка Happ/Incy | Выполняется на устройстве. Адрес подписки не передаётся сервисам расшифровки. После расшифровки провайдер получает обычный запрос подписки и выбранные пользователем заголовки. |

Закреплённое ядро — `THRONE_CORE_REF=93e4873c56c2285f647d0146a0df9c088f122910`. Мобильная обвязка создаёт Xray непосредственно в процессе, не добавляя gRPC API: [constructor.go](https://github.com/ttrroyy/qThrone/blob/93e4873c56c2285f647d0146a0df9c088f122910/core/internal/xray/constructor.go), [mobile/xray.go](https://github.com/ttrroyy/qThrone/blob/93e4873c56c2285f647d0146a0df9c088f122910/core/mobile/xray.go).

Закреплённый Xray — `throneproj/xray-core@e662c22ab109`. Его SOCKS UDP listener создаётся после авторизованного TCP UDP ASSOCIATE, а не постоянно на общем SOCKS-порту: [protocol.go](https://github.com/throneproj/xray-core/blob/e662c22ab109/proxy/socks/protocol.go), [server.go](https://github.com/throneproj/xray-core/blob/e662c22ab109/proxy/socks/server.go). Поэтому совет отключить весь UDP из статьи нельзя механически применять к этой версии и ломать UDP-трафик туннеля.

`VpnListenerPolicyTest` проверяет отказ для открытых API, SOCKS без пароля, слабых реквизитов и Xray-входов на всех интерфейсах. `AndroidVpnListenerTest` проверяет отсутствие стандартных прокси/DNS-слушателей в VPN даже при старых настройках. Android-тест `LocalProxySecurityTest` запускает оба встроенных ядра и проверяет реальное SOCKS-рукопожатие: отказ анонимному клиенту и допуск внутренних реквизитов. Результаты выполнения находятся в GitHub Actions соответствующего коммита.

Проверка не обещает скрыть факт VPN от ОС, root-процессов или сетевого оператора. Режим «только прокси» намеренно предоставляет локальный прокси и использует выбранные пользователем настройки авторизации; это отдельный режим от VPN с выбором приложений.
