• Новые протоколы: DNSTT, VayDNS, SlipStream, MasterDNS и S3 Bypass. Каждый работает через клиент из исходников оригинального проекта и подключается через локальный мост с паролем, как остальные встроенные транспорты: раздельная маршрутизация и параллельный тест пинга работают и не затрагивают активный туннель.
• Профили DNS-туннелей добавляются из буфера обмена, по QR-коду, из файла или вручную: поддерживаются ссылки dnst:// (обе формы спецификации), slipnet:// и masterdns://. S3 Bypass импортируется из конфигурации Xray с outbound fedarisha.
• Редактор DNS-туннелей: список резолверов (UDP, DoH и DoT), тип записи, бэкенд SOCKS5, SSH или Shadowsocks, сертификат и congestion control для SlipStream, ключ и метод шифрования для MasterDNS. Если резолверы не указаны, используются DNS текущей сети.
• TrustTunnel подключается как официальный клиент: сначала QUIC, через секунду параллельно HTTP/2 (сразу, если QUIC не ответил), побеждает первый установленный. Тест пинга профиля с QUIC учитывает эту схему и проходит через HTTP/2, если QUIC заблокирован.
• CSQTT получает хеши из привязки аккаунта VK: в профилях CSQTT доступен режим «Авто». Звонки создаёт только механизм qWDTT, CSQTT подключается к ним анонимно и не входит в аккаунт VK.
• Добавлена проверка хешей CSQTT, как у qWDTT.
• Капча qWDTT и CSQTT работает как в оригинальных приложениях: каждый клиент снова ждёт решения столько же, сколько оригинал (10 секунд для автоматической попытки, минута для ручного окна), а окно капчи повторяет поведение оригинала нужного клиента.
• Автоматическая попытка решения капчи нажимает чекбокс с теми же паузами и касанием, что оригинал, и сразу передаёт управление ручному окну, если VK показал слайдер, вместо ожидания таймаута.
• Ручное окно капчи закрывается само через минуту, как в оригинале, и не закрывается от жеста «назад» или смахивания: отказом считается только кнопка закрытия. Уведомление «Откройте приложение» больше не появляется для автоматических попыток, а успешно решённая капча не считается ошибкой подключения.
